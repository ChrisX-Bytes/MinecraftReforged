## 目标
完全复刻 MC Java 版水流动机制（依据 minecraft.wiki/w/Fluid + DeepSeek 分析），重写 `FluidSimulator::processSource`。

## 只改一个文件
`cpp/src/fluid_simulator.cpp` 的 `processSource()`（第 102-241 行）。其余文件（encode/decode、schedule、tick、Python 集成、buildMesh 渲染）全部不动。

## 当前实现的问题
1. **push 模型与 receiver 模型混用冲突**：第 2 步（receiver 重算 `bestFeeder`）和第 4 步（push `myLevel+1`）在同一方块上跑两套不同模型，收敛慢、行为怪异。
2. **无限水源判断 `belowSupports = (below != BLOCK_AIR)` 过宽**：把流水(level 1-7)也算支撑，但 Wiki 规定下方须是"液体流不进的方块"（固体或水源）。
3. **level-7 feeder 未排除**：邻居 level 7 不应再供给（7+1=8 超界），当前代码路径不清晰。
4. header 注释过期（wy 标 20 位，实际 16 位）。

## 新 processSource 算法（严格对齐 MC Java）

读取 `id, myLevel, above, below`。分 4 阶段：

**阶段 1 — 无限水源形成（仅对非源水流块）**
- 条件：`myLevel != 0`（当前是流水，非源）`&& below` 是固体或水源（`below != AIR && below != WATER`，或 `below == WATER && level(below)==0`）`&&` 水平 4 邻居中**水源(level 0)** 数 ≥ 2
- 动作：变为源 `setBlock WATER + setWaterLevel 0`，markDirty，schedule 6 邻居，`myLevel = 0`

**阶段 2 — 重算本方块应有水位（receiver 模型，仅流水块 level≠0）**
- `if (above == WATER)` → `targetLevel = 8`（下落柱的一部分）
- `else` 扫 4 水平邻居：取最小"有效供给水位" `minInput`
  - 邻居是 WATER 时：`eff = (nl==8) ? 0 : nl`（下落柱按源 0 供给）
  - **只有 `eff <= 6` 才算有效供给**（level 7 无法供给，7+1=8 超界）
  - `minInput = min(minInput, eff)`
- `if (minInput 无供给)` → **干涸**：`setBlock AIR + setWaterLevel 0`，markDirty，schedule 6 邻居，`return`
- `targetLevel = minInput + 1`（结果 1..7）
- `if (targetLevel != myLevel)` → `setWaterLevel targetLevel`，markDirty，schedule 6 邻居，`myLevel = targetLevel`

**阶段 3 — 向下流（below 是空气）**
- `if (below == BLOCK_AIR)`：在下方生成下落水 `setBlock(x,y-1,z) WATER level 8`，markDirty，schedule，`return`
- Wiki 规则：下方是空气时只直落，不水平扩散（return）。含 source 也遵循——source 的 below 是固体才扩散，below 是空气就落下。

**阶段 4 — 水平扩散（below 是固体/水）**
- 算 `pushLevel`：
  - `myLevel == 0`（源）→ `pushLevel = 1`
  - `myLevel == 8`（下落柱）→ 此时 below 必固体（阶段 3 已 return 空气情况）→ `pushLevel = 1`（落地点按源级扩散）
  - 其余 → `pushLevel = myLevel + 1`
- `if (pushLevel > 7)` → 源/下落柱仍 `schedule(self, 5)` 保持活跃，`return`
- `schedule(self, 5)`（源和下落柱持续驱动扩散；流水块也会周期重算以便干涸收敛）
- 扫 4 水平邻居：
  - 邻居是 AIR → `setBlock WATER pushLevel`，markDirty，schedule
  - 邻居是 WATER 且 `nl != 0 && nl != 8 && nl > pushLevel` → 降低其水位到 `pushLevel`（收敛），markDirty，schedule

## MC 行为对照（防回归）
- **平地单水源**：源→扩散1→…→7，菱形 7 格 ✓
- **悬崖边水源**：源 below=固体扩散 level 1；边缘邻居 below=空气→落下成柱 ✓
- **下落柱**：每层只下落(below空气 return)；落地点(below固体)扩散 level 1 菱形 ✓
- **水池表面**：源块 myLevel==0 跳过阶段2，保持源 ✓
- **下落柱入水池**：池面源块 above=水但 myLevel==0 不变 8 ✓
- **海洋**：海量源块 level 0，互相供给但跳过重算，稳定 ✓
- **挖掉水源**：下游流水阶段2失去供给→干涸→级联 schedule 邻居→逐级干涸 ✓
- **无限水**：2×2 坑四角成源（每格 2 个源邻居 + below 固体）✓
